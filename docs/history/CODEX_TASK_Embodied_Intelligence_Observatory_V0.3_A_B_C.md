# Codex 改进任务：Embodied Intelligence Observatory V0.3
## 目标：从“论文/新闻汇总”升级为“近期具身智能变化 + 场景与教育影响判断”的图文周刊

> 当前样稿：`2026-W40.md`
> 当前阶段：人工运行验证期
> 本阶段仍不做定时云端自动化

---

# 0. 产品定位重新定义

本项目的第一目标不是“覆盖最多论文”，也不是“给研究者做论文灵感库”。

它的核心价值优先级如下：

## A. 第一优先级：告诉读者最近具身智能最重要的事情和趋势

读者打开页面后，应该快速知道：

- 最近真正发生了什么重要变化；
- 哪些事情值得持续关注；
- 哪些只是热闹，暂时还不能下结论；
- 与一个月前相比，行业/技术方向发生了什么变化。

## B. 第二优先级：解释这些变化对真实应用和教育意味着什么

重点回答：

- 对工业制造 / 装配有什么影响？
- 对仓储物流 / 搬运有什么影响？
- 对零售 / 商业服务有什么影响？
- 对家庭 / 养老 / 服务机器人有什么影响？
- 对医疗 / 康复有什么影响？
- 对城市环卫 / 户外作业有什么影响？
- 对巡检 / 安防 / 边防有什么影响？
- 对农业 / 野外机器人有什么影响？
- 对通用人形机器人有什么影响？
- 对具身智能课程、专业建设、人才培养和学生学习有什么启发？

## C. 第三优先级：研究启示

保留，但不要让整份周刊重新变成“论文解读项目”。

研究部分更适合回答：

- 最近出现了什么值得研究者继续追的问题？
- 哪些 benchmark / 方法 / 失败模式值得复查？
- 哪几篇论文值得精读？

## D. 教育启示

教育不再做成孤立、经常为空的“教育新闻栏目”。

教育应同时进入“影响分析”：

- 新技术意味着学生需要增加什么能力？
- 哪些内容已经值得进入课程？
- 哪些仍然只适合作为前沿拓展？
- 哪些公开课程 / 教材 / 项目适合继续学习？

# 1. 一个核心原则：周报是发布频率，不是信息窗口

今后不要把“周报”理解成：

> 只允许写最近 7 天首次发布的信息。

采用三层时间窗口：

## Weekly New｜最近 7 天

真正的新事件、新论文、新项目、新政策。

## Recent Major｜最近 30 天

过去 30 天内仍然影响当前判断的重要事件。

## Persistent Major｜重大持续事件

极其重要的事件，只要仍有新进展或仍然构成当前行业背景，可以保留 45–60 天。

例如：

- 重大并购
- 机器人基础模型发布
- 头部公司重大产品路线变化
- 国家级具身智能政策
- 关键开源平台
- 大规模真实部署
- 重大 benchmark / 真实机器人评测

因此：

> 跨过自然周，不等于事件失去价值。

# 2. 建立 Major Event Memory

新增：

```text
data/major_events.json
```

每个重大事件建议包含：

```json
{
  "id": "",
  "title": "",
  "event_date": "",
  "first_seen": "",
  "last_updated": "",
  "importance": "S|A|B",
  "status": "new|developing|stable|archived",
  "summary": "",
  "why_it_matters": "",
  "what_changed_since_last_issue": "",
  "categories": [],
  "application_scenarios": [],
  "education_implications": [],
  "research_implications": [],
  "sources": []
}
```

建议：

- S 级：重大产业/技术/政策变化，可持续跟踪 4–8 周
- A 级：高价值事件，可持续 2–4 周
- B 级：普通但有价值的新信息，主要放在当期

每周生成时：

1. 检查本周新增；
2. 检查最近 30 天大事；
3. 检查 S/A 级事件是否有后续变化；
4. 决定继续展示、降级或归档。

# 3. 首页先给“判断”，不要先给论文列表

当前页面首屏不应直接是一串论文。

新的 Hero 至少包含：

## Embodied Intelligence Weekly
### YYYY · Week XX

### 本期一句话

用一句编辑判断概括这一期。

例如：

> 世界模型正在从“生成未来画面”进一步进入数据选择、动作筛选和机器人训练闭环。

### 最近最重要的 3 个变化

每条 1–2 句：

1. 发生了什么
2. 为什么值得关注

### 本期覆盖

例如：

```text
4 major developments
6 papers worth reading
3 application signals
2 education signals
14 primary sources checked
```

不要在 Hero 放 debug / source error。

# 4. 页面顺序重新设计

最终网页建议按以下顺序：

1. Hero：一句话主题 + 3 个核心判断
2. 10 分钟速读
3. 最近 30 天大事时间线
4. Top Stories
5. Impact Radar：应用与教育影响
6. Industry / Product / Open Source
7. Research Radar
8. Papers Worth Reading
9. Learning / Education
10. Sources / Methodology（折叠）

# 5. 10 分钟速读

选择 5–7 条真正值得知道的内容。

不要全部来自论文。

建议构成：

- 1–2 条产业 / 公司
- 1–2 条关键技术 / 平台
- 1–2 条论文 / benchmark
- 0–1 条教育 / 政策

每条只写：

```text
标题
一句话：发生了什么
一句话：为什么值得关注
标签
```

目标：

> 读者只看这一屏，也能知道最近发生了什么。

---

# 6. 最近 30 天大事 Timeline

生成一张有信息量的时间线。

例如：

```text
Sep 08   重大模型
Sep 14   开源平台
Sep 21   商业部署
Sep 29   并购 / 融资
Oct 02   Benchmark / Paper
```

每个节点支持：

- category
- importance
- link
- status

不要把所有事件都放进 Timeline。

只保留：

> 最近一个月中足以影响行业理解的事件。

# 7. Top Stories：每期只做 3–5 个重点

不要把 Top Stories 做成“论文卡片”。

重点事件可以来自：

- 企业
- 产品
- 技术
- 论文
- 开源
- 政策
- 教育

每个 Top Story 使用：

## 标题

### 一句话看懂

普通技术读者也能理解。

### 发生了什么

用 1–2 段解释事实。

### 为什么现在重要

解释它为什么值得在本期进入 Top Story。

### 对应用场景有什么影响

只选真正相关的场景。

例如：

```text
仓储物流
工业装配
家庭服务
```

### 对具身智能教育有什么启发

如果相关，回答：

- 是否值得进入本科 / 高职课程？
- 更适合作为基础能力还是前沿专题？
- 学生需要补什么前置知识？
- 是否已有可以用于教学的开源资源？

### 研究上值得继续追什么

最多 2–3 条。

### 仍需验证

集中写关键边界。

### Sources

使用一手来源。

# 8. Impact Radar：这是项目的重要特色

将“应用启示 + 教育启示”升级为独立栏目。

## 8.1 应用场景分类

建议固定一级分类：

- 工业制造 / 装配
- 仓储 / 物流 / 搬运
- 零售 / 商业服务
- 家庭 / 养老 / 服务机器人
- 医疗 / 康复
- 城市环卫 / 户外作业
- 巡检 / 安防 / 边防
- 农业 / 野外环境
- 通用人形机器人
- 教育 / 科研平台

每期只展示真正有信号的场景。

---

## 8.2 每个场景回答三个问题

### 最近出现了什么新信号？

### 可能改善哪类能力？

例如：

- 感知
- 定位
- 长程任务
- 抓取
- 灵巧操作
- 任务规划
- 数据采集
- 控制
- 跨本体复用

### 距离真实部署还有什么缺口？

例如：

- 可靠性
- 节拍
- 成本
- 真机数据
- IP / 防护
- 安全
- 长时间运行
- 硬件依赖
- 人工遥操作依赖

# 10. 教育启示不要只依赖“本周教育新闻”

教育是本项目区别于普通论文周报的重要特色。

即使本周没有教育政策或高校新闻，也可以基于本期技术变化回答：

## 对课程有什么启示？

例如：

- World Model 已经值得进入“具身智能前沿”模块，但不适合替代基础机器人学；
- Robot Memory 可以作为长时序任务 / 部分可观测问题的案例；
- Cross-Embodiment 可以用于讲解泛化与机器人形态差异。

## 对学生能力有什么启示？

例如：

- 机器人基础
- 控制
- ROS
- 仿真
- 数据
- 深度学习
- 强化学习
- 视觉
- 机械臂
- 系统验证

## 本期值得学习的 1–3 个概念

每个给：

```text
概念
一句解释
推荐论文 / 课程 / 开源项目
```

# 11. Research Radar：降低权重，但提高价值密度

不要再用大量篇幅逐篇平铺论文。

先给：

## 最近研究正在解决什么？

聚合本期和最近 30 天论文主题。

例如：

```text
World Models
Memory
Skill Composition
Cross-Embodiment
Robot Data
```

然后总结：

### 最近形成了哪些研究线索？

### 哪些问题仍明显没有解决？

### 哪些结果值得复现？

### 哪些 benchmark 值得关注？

# 13. 产业栏目不能长期为空

如果最近 7 天没有产业一级大新闻：

不要直接输出：

> 本期已接入来源未检出足够信息。

改为：

> 本周没有新的一级产业事件，下面两项最近 30 天的重要变化仍值得继续跟踪。

因此产业区允许使用：

- 本周新增
- 最近 30 天 Major Event
- 重大事件后续更新

# 14. “大新闻兜底”必须独立于普通 Collector

每次生成前执行 Major News Audit。

重点检查：

## Companies

头部具身智能 / AI / 机器人公司。

## Product

机器人、机械臂、灵巧手、传感器、计算平台。

## Models

VLA、World Model、Robot Foundation Model。

## Open Source

重大模型 / 数据 / 仿真 / 工具发布。

## Capital

重大融资、并购。

## Policy

国家 / 行业重要政策。

## Education

新专业、微专业、培养方案、重要课程体系。

输出：

```text
runs/YYYY-WXX-major-news-audit.json
```

如果普通 Pipeline 没收录，但 Audit 发现明显大新闻：

必须进入人工复核。

# 18. 写作风格

## 先给结论，再给细节

每个重点内容先有：

> 一句话看懂

---

## 标题要有读者价值

避免只有论文名翻译。

例如：

> 同一套“行为能力”能跨人形机器人迁移吗？CrossBFM 给出了边界很清楚的结果

---

## 每段 2–4 句

减少长段落。

---

## 减少模板味

不要所有条目都机械重复完全相同的小标题。

---

## 限制“防御性语言”数量

严谨性保留，但把核心风险集中在：

> 仍需验证

避免正文反复出现：

- 不能说明
- 不能证明
- 尚不能

# 19. 面向读者的内容比例

建议作为编辑参考，不要求机械执行：

## 45–50%

最近最重要变化 / 大新闻 / 趋势。

## 25–30%

应用场景影响 + 教育启示。

## 10–15%

研究趋势与研究启示。

## 10–15%

论文 / 工具 / 学习资源入口。

论文是证据和深度阅读入口，不再天然占据最大篇幅。
