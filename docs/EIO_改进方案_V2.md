## 一、反思：上一版为什么偏了

上一版样刊把四起收购放在最前面，语气接近投资周报。问题不在排版，而在三个更底层的设定。

1. **“重要性”按事件规模来衡量。** 金额、估值、交易规模天然最大，所以资本新闻总排在前面。但核心读者（工程师、开发者、产品经理、项目经理、教育者）关心的是：这件事改变了哪个场景的可行性，哪个工具我能用，哪个产品值得选型，哪项能力需要教。
2. **内容的基本单位是“新闻”，没有累积。** 每期写完就过去了，读者无法回答“仓储场景现在到哪一步了”“灵巧手现在有哪些可选”。研究类周报已经很多，而**场景和产品的持续追踪**几乎没人做，这才是本项目的空位。
3. **周刊节奏太紧，只能追新闻。** 每周一期，维护成本高，也更容易漏掉热点。改成双周后，有余量做一个案例拆透，并把场景地图和产品库维护好。

## 二、定位

**一句话：看具身智能在真实场景里走到了哪一步：哪些产品能买，哪些工具能用，学校该教什么。**

| | 学术类周报（已有很多） | 投资类资讯（不做投资分析） | 本项目 |
|---|---|---|---|
| 核心对象 | 论文 | 融资、估值 | 场景、产品、工具、人才 |
| 判断标准 | 方法新颖性 | 金额、热度 | 落地证据、可用性、可借鉴性 |
| 读者问题 | 有什么新方法 | 谁值钱 | 我能用什么，该关注哪个场景，该教什么 |
| 长期资产 | 论文列表 | — | 场景地图、产品库、工具表、故事线 |

**核心读者与优先级：**

1. 算法工程师和开发者；
2. 产品经理和项目经理；
3. 教育界专业人士。

**地域：** 中外均衡，按事件重要性自然分布，不预设比例。

**资本信息：** 重大投融资和并购要写，而且放在正文最前面。
- **“重大”怎么判断：先看对行业的影响力，再看金额。**
  1. **影响力（主要依据）：** 是否改变竞争格局或产业链位置，比如巨头入场、关键技术或团队被整合；是否影响开发者常用的工具和技术栈；是否影响一类场景的可行性或供给；是否成为行业的风向标，比如头部公司上市或首个大额订单。
  2. **金额（次要参考）：** 金额大但影响有限的（比如财务投资、老股转让）可以降级；金额小或未披露但影响大的（比如高通收购 MoveIt 维护者 PickNik）照样收录。约 1 亿美元可以作为“值得看一眼”的参考线，不作为硬门槛。
- **写法：** 从从业者角度写，即这件事对产品路线、技术栈、开发工具、人才流向意味着什么。不做估值分析，不写股价走势。
- **小额融资：** 不单独成条；需要时在场景或产品条目里顺带提一句。

## 三、选题标准（替换原评分）

| 维度 | 权重 | 看什么 |
|---|---|---|
| 落地证据 | 25% | 是否进入真实场景；规模；有没有运行数据（时长、成功率、节拍、干预次数） |
| 可用性与可借鉴性 | 25% | 工程师能否用上（开源、可购买、有 SDK），产品经理和项目经理能否借鉴（方案、指标、流程） |
| 能力边界变化 | 20% | 是否让某类任务或场景从“做不到”变成“能试” |
| 影响面 | 15% | 影响一个产品，还是一类场景或整个开发生态 |
| 证据质量 | 10% | 官方、多方确认 > 公司自述 > 媒体报道 |
| 教育价值 | 5% | 能否直接进课程、实训或竞赛 |

**说明：** 重大投融资不参与这套评分，单独按“影响力优先、金额其次”判断，放在“格局变化”栏目，按影响力排序。

**明确降权的内容：** 小额融资、估值和股价讨论、只有概念视频没有任务数据的发布、重复的 PR 稿。

## 四、写作口径

- **点到为止，给链接。** 每条按固定结构写：
  - 是什么；
  - 能不能用（或能不能借鉴）；
  - 对研发、产品和项目、教育分别意味着什么；
  - 还缺什么证据。
  
  技术细节留给原文。
- **用工程师的语言，不用投资人的语言。** 写“任务成功率”“节拍”“接管次数”“许可证”“硬件门槛”，不写“赛道”“估值逻辑”“风口”。
- **证据等级用标签展示**（官方确认 / 公司自述 / 媒体报道 / 推断），正文不堆免责语。
- **分角色要点从四类改成三类：**
  - 研发：算法、开发；
  - 产品与项目：产品经理、项目经理；
  - 教育。
- **篇幅：** 主体 25 分钟以上，首屏 3 分钟能读完要点。篇幅来自覆盖面和一篇深度案例，不来自每条写得更长。
- **语言：** 中文为主，每期附一页英文摘要。专有名词保留英文。

## 五、栏目结构（双周刊，一期）

| # | 栏目 | 内容 | 主要可视化 |
|---|---|---|---|
| 0 | 封面 | 期号、时间窗口、本期主题一句话、官方大图 | 大图 + 主题 |
| 1 | 两周要点 | 8–10 条，每条一句话，3 分钟读完 | 无 |
| 2 | **格局变化：重大投融资与并购** | 按行业影响力选取和排序，金额其次；每条写清对产品、技术栈、工具、人才的影响 | **交易地图**（时间 × 金额 × 类型）；涉及技术栈时附技术栈地图 |
| 3 | **场景落地** | 按场景（工厂、仓储、零售、家庭、医疗康复、户外巡检、教育科研……）列出本期落地事件，标出部署阶段、规模和缺口 | **场景成熟度地图**（场景 × 演示 → 试点 → 小批量 → 规模化） |
| 4 | **产品与发布** | 新机器人、灵巧手、平台、核心部件 | **产品档案卡** + 同类对比 |
| 5 | **技术动态** | 模型、工具链、开源、仿真、数据集，点到为止 | **工具与模型可用性表** |
| 6 | 教育与人才 | 专业建设、职业教育、课程资源、竞赛与 K12、岗位能力需求 | 岗位能力 ↔ 课程映射 |
| 7 | 研究速览 | 3–5 篇，只写与落地的关系 | 无 |
| 8 | 故事线 | 持续追踪的主线，只写本期新进展 | 时间轴 |
| 9 | **深度阅读：落地案例拆解** | 每期拆透一个真实部署：任务、系统结构、流程、指标、可借鉴之处、缺口 | 架构图、流程图、指标对照 |
| 10 | 本期复盘 | 漏检比对、来源说明 | 无 |

**排序逻辑：** 先给全局（要点 → 格局变化），再按读者关心的主体内容展开（场景 → 产品 → 技术 → 教育），最后是进阶内容（研究 → 故事线 → 深度案例）。案例拆解放在最后，留给愿意读到底的深度读者；首屏和导航里提供直达链接，想直接看案例的读者不用滚到底。
| — | English Summary | 独立页面 | 无 |

**站点常设页面（跨期累积，是项目的长期资产）：**

- **场景地图：** 每个场景的成熟度和历次证据；
- **产品库：** 所有产品档案卡，可按类型、价格、开放程度筛选；
- **工具表：** 模型、工具链、开源项目的可用性和版本；
- **故事线：** 每条主线的完整时间轴；
- **往期归档。**

## 六、表现形式

### 6.1 视觉：Claude 羊皮卷风格

依据 voltagent/awesome-design-md 中的 Claude DESIGN.md：

- **底色与表面：**
  - 页面底色 Canvas `#faf9f5`；
  - 卡片 `#efe9de`；
  - 柔和分隔带 `#f5f0e8`；
  - 强调区块 `#e8e0d2`；
  - 深色区块 `#181715`，用于案例拆解和数据面板。
- **文字：**
  - 主文字 Ink `#141413`；
  - 正文 Body `#3d3d3a`；
  - 次要文字 Muted `#6c6a64`；
  - 发丝线 `#e6dfd8`。
- **强调色：**
  - 珊瑚色 `#cc785c`，只用于少量强调和号召区块；
  - 辅助色青 `#5db8a6`、琥珀 `#e8a55a`，用于数据图表和类别标签。
- **字体：**
  - 标题用衬线体、字重 400、负字距：中文用思源宋体（Noto Serif SC），西文用 Source Serif 4；
  - 正文用 Inter + 思源黑体；
  - 数据和代码用 JetBrains Mono。
- **节奏：**
  - 区块按 奶油底 → 卡片色 → 深色 → 奶油底 交替，避免相邻区块同色；
  - 大区块之间留足 96px 间距；
  - 靠色块深浅区分层次，几乎不用阴影。
- **深色模式：** 用设计稿中的 Surface Dark 系列推导，图表配色在深浅两种底色上分别校验。

### 6.2 生成方式：借鉴 answer-me-with-html

借鉴的不是它的外观，而是它的架构：**模型只写内容，渲染器负责把内容变成图。**

- 每期内容是一份 Markdown 文件：YAML 头部写期号、窗口、主题，正文里用带类型的代码块描述可视化。
- 渲染器把这些块转成统一风格的图表和组件，输出单个静态 HTML。
- **好处：**
  - 我写作时的输出量大幅减少；
  - 每期视觉保持一致；
  - 改一处样式，全站同步。
- **本项目需要的组件：**

| 块 | 用途 |
|---|---|
| `scene-map` | 场景成熟度地图，数据来自场景库 |
| `product-card` | 产品档案卡，数据来自产品库 |
| `compare` | 产品或工具对比表，附结论 |
| `tools` | 可用性表（现在可用 / 抢先体验 / 未开放、许可、硬件门槛） |
| `flow` | 系统架构和流程图，自动布局（案例拆解用） |
| `sequence` | 人机交互或多系统协作的时序 |
| `timeline` | 故事线和事件时间轴 |
| `stack` | 技术栈地图 |
| `metric` | 指标对照（如成功率 vs 目标、机器人节拍 vs 人工节拍） |
| `skills-map` | 岗位能力 ↔ 课程映射 |
| `kv` / `callout` / `role` | 事实卡、判断提示、分角色要点 |
| `figure` | 官方配图 + 署名与链接 |

  - **排序思路：** 先放最吸引人、最有画面感的内容（大交易、价格表），再用“一张图”过渡到场景，最后才是需要细读的部分。
  - **文风规范：**
    - 像杂志编辑那样写：标题用具体的动作和数字；导语讲故事，有画面。
    - 谨慎说明交给证据标签和一条编后，正文不反复写“不能当作”“需要注意”。
    - 少用“意味着”“值得关注”“赛道”这类套话。
    - 少用冒号揭晓式的句子，不用破折号插入语。
